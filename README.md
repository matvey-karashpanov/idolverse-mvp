# IDOLVERSE

IDOLVERSE — одностраничное веб-приложение-каталог K-pop, C-pop и J-pop исполнителей и музыкальных групп.

- **Демо:** https://matvey-karashpanov.github.io/idolverse-mvp/
- **Репозиторий:** https://github.com/matvey-karashpanov/idolverse-mvp

## Возможности

- Каталоги артистов и групп с поиском и фильтрами.
- Профили артистов и музыкальных групп.
- Новости и связанные материалы.
- Форма обратной связи.
- Административная панель для управления контентом и обращениями.

## Технологии

React 18, TypeScript, Vite, Redux Toolkit, React Router, CSS, Vitest и React Testing Library.

## Запуск проекта для разработки

### 1. Установите необходимые инструменты

Перед началом работы установите:

- **Git** — для клонирования репозитория;
- **Node.js** (рекомендуется актуальная LTS-версия);
- **npm** — устанавливается вместе с Node.js.

Проверьте, что инструменты доступны в терминале:

```bash
git --version
node --version
npm --version
```

### 2. Склонируйте репозиторий

```bash
git clone https://github.com/matvey-karashpanov/idolverse-mvp.git
cd idolverse-mvp
```

Если проект уже скачан архивом, распакуйте его и откройте терминал в папке, где находится `package.json`.

### 3. Установите зависимости

```bash
npm ci
```

Команда устанавливает зависимости по `package-lock.json`. При обычной установке для разработки не нужно вручную устанавливать React, Vite или другие пакеты.

### 4. Запустите локальный сервер

```bash
npm run dev
```

После запуска Vite выведет локальный адрес, обычно:

```text
http://localhost:5173/
```

Откройте этот адрес в браузере. Пока команда `npm run dev` выполняется, изменения в исходном коде будут автоматически отображаться в приложении.

Чтобы остановить сервер, нажмите `Ctrl + C` в терминале.

## Проверка перед отправкой изменений

Запустите тесты:

```bash
npm test
```

Соберите production-версию:

```bash
npm run build
```

Для локального просмотра уже собранной версии:

```bash
npm run preview
```

Vite выведет адрес preview-сервера в терминале.


## Структура проекта

```text
src/
  app/          # настройка Redux store и типизированные хуки
  components/   # переиспользуемые компоненты
  data/         # исходные демонстрационные данные
  domain/       # логика каталога и работа с данными
  features/     # Redux-слайсы и связанная функциональность
  pages/        # страницы приложения
  utils/        # вспомогательные функции
public/         # статические файлы
```

## Данные и ограничения MVP

На этапе frontend MVP приложение использует демонстрационные данные и `localStorage`. Изменения сохраняются в браузере текущего пользователя и не синхронизируются между устройствами или разными пользователями.

Вход в административную панель демонстрационный. Это не серверная авторизация и не предназначено для защиты реальных пользовательских данных. Подключение собственного backend и постоянной базы данных относится к следующему этапу разработки.

## Публикация

Проект публикуется на GitHub Pages с помощью GitHub Actions. После отправки изменений в основную ветку workflow устанавливает зависимости, запускает тесты, собирает приложение и выполняет публикацию.

Для локальной разработки файл `.env` не требуется.
